## 2. 对产品目标的理解

产品是一个中文界面的 Windows 10/11 离线桌面学习软件。用户首次导入自己持有的英文教材，此后教材、结构化阅读内容、搜索索引和个人学习记录均在本机使用。

核心交付链路：安装 → 本地导入 → 阅读 HTML 与原书 → 批注与记忆位置 → 重启恢复 → 检索与复习 → 备份恢复。

需要同时保有两份表达：

1. 原 PDF：科学图表、公式和排版的校对依据。
2. 有页码来源的结构化内容：支撑可重排的 HTML、搜索、批注和知识卡片。

原书模式不能代替 HTML；HTML 的自动转换也不能假定可以无损重建整书。遇到低置信度内容，保留原书对应区域，显式记录待校对问题。

首版范围包括三种阅读模式、7 Part/31 Chapter 导航、个人学习数据、全文搜索、仪表盘、基本学习计划、知识卡片、复习中心，以及题库和双语的数据扩展接口。首版不包括整书翻译、官方题库、云同步或在线 AI。

附件给出的 1,057 页、7 大部分、31 章是目标教材描述。实现时必须核验实际 PDF 页数、页标签和目录；不能凭描述伪造章节页码或 Section 名称。

## 3. 推荐技术决策

| 层次 | 首选方案 | 实施约束 |
| --- | --- | --- |
| 桌面外壳 | Electron | 阶段一确定仍支持目标 Windows 版本的受维护稳定版并锁定 |
| 界面 | React + TypeScript + Vite | 中文 UI，正文英文；运行资源全部随包提供 |
| 本地数据 | SQLite + better-sqlite3 | 在专用数据进程使用；尽早验证 Electron 原生模块重建和 Windows 打包 |
| PDF 阅读与基础提取 | pdfjs-dist | 主库与 worker 版本一致；字体、CMaps 等资源离线打包 |
| PDF 区域渲染 | PDF.js 配合经验证的本地 Canvas 实现 | 候选为 @napi-rs/canvas；必须先证明 Windows 包可执行，再固定依赖 |
| 搜索 | SQLite FTS5 | 在实际打包运行时验证可用；结果关联块、章节和 PDF 页 |
| 包装交付 | electron-builder，NSIS 安装包及便携 ZIP | 优先 Windows x64；其他架构不默认列入首版 |
| 验证 | Vitest、Playwright/Electron、Windows 实机检查 | 单元、集成、桌面操作和安装验证各有责任 |

这是建议架构，具体版本在第一阶段通过兼容性试验后写入 ADR 和锁文件。不要安装所有库的最新版后才处理不兼容。

运行进程划分：

- Renderer：React 界面、HTML 阅读、PDF 显示；不直接读写 SQLite 或任意本地路径。
- Preload：小而明确的类型化 API，使用运行时 schema 校验输入；不暴露通用文件系统或任意 IPC 调用。
- Main：窗口、文件选择、用户数据目录、受限资源协议、进程生命周期和任务协调。
- 数据进程：单一 SQLite 写入入口、查询、迁移、备份快照。
- 导入进程：提取、布局分析、资产生成和分批输出。与数据进程之间使用有界批次和背压。

主窗口开启 contextIsolation、sandbox，关闭 nodeIntegration。教材内容不作为任意 HTML 注入，结构化 AST 经受控组件渲染；笔记 Markdown 禁用原始 HTML。资源通过受限本地协议读取，校验路径归属。

不预设必须引入 Python 服务、外部数据库或远程 OCR。若原书抽样证明 PDF.js 方案无法达到阅读顺序、表格或公式要求，先建立失败样例和改进对比，再决定是否引入随软件分发的本地解析辅助进程。届时把许可证、模型/二进制大小、离线依赖和 Windows 打包验证纳入决策，不允许运行时再联网下载必需组件。

## 4. 项目组织与数据存储

建议采用单仓库、单应用，先避免多应用 monorepo 的额外复杂度：

```text
src/
  main/                  # Electron、资源协议、任务协调
  preload/               # 类型化桌面 API
  renderer/              # 页面、阅读器、笔记和学习模块
  workers/               # 导入进程、数据进程入口
  shared/                # IPC schema、领域类型、错误码
  domain/                # 内容、锚点、计划、复习等纯逻辑
  storage/               # SQLite schema、迁移、仓储
  importer/              # PDF 提取、布局分析、内容生成
tests/
  fixtures/              # 自建、可分发的 PDF 测试样例
  unit/
  integration/
  e2e/
scripts/                 # Windows 构建、产物检查脚本
docs/
  architecture.md
  data-model.md
  ipc-contracts.md
  acceptance-matrix.md
  handoff.md
```

应用数据根目录通过 `app.getPath('userData')` 获取并保持稳定。建议结构：

```text
<userData>/
  library.sqlite
  library.sqlite-wal / library.sqlite-shm
  books/<edition-id>/source.pdf
  books/<edition-id>/revisions/<revision-id>/assets/
  staging/<job-id>/
  backups/
  logs/
```

安装路径与用户资料路径分离。便携版默认也使用稳定 userData 路径，避免解压覆盖导致学习资料丢失；“所有数据跟随 EXE”的 U 盘模式如需支持，应另做明确设计。

固定 appId 和用户数据目录策略。升级时先迁移前备份，再事务化执行数据库迁移。卸载默认保留用户数据；清空资料必须由用户显式操作。支持“打开资料目录”和“导出备份”。SQLite WAL 不能通过简单复制主数据库文件来备份，应使用在线备份接口或受控关闭后的完整复制。

## 5. 数据模型：先冻结身份和来源，再写 UI

### 5.1 教材与转换结果

- `works`：教材作品身份，不直接等于一个 PDF 文件。
- `editions`：语言、版本、源文件 SHA-256、页数、导入状态；同一作品可有英文和中文版本。
- `source_pages`：PDF 内部零基索引、界面一基页码、印刷页标签、尺寸和旋转。
- `toc_nodes`：Part/Chapter/Section 层级、顺序、来源、页范围、识别置信度。
- `content_revisions`：转换器版本、配置版本、创建时间、质量状态。
- `content_blocks`：稳定块 ID、所属版本、类型、结构化正文、章节归属、阅读顺序、来源定位。
- `block_sources`：块与一个或多个页区域的映射，允许跨页段落、表格和图题。
- `assets`：图、表、公式、局部保真图的路径、摘要、尺寸、caption、来源区域和生成状态。
- `import_jobs`、`import_page_tasks`：任务阶段、页级进度、重试与检查点。
- `conversion_issues`：低置信度读序、未分配正文、疑似缺图、目录冲突等可追溯问题。

AST 区分 heading、paragraph、list、table、figure、equation、caption 等块类型。不能仅保存整章 HTML 字符串或用一个大字段容纳全部正文。

文本有三种必要表示：原始提取结果、适合阅读的显示文本、适合搜索的规范化文本。保留字符映射，防止去连字符、空白合并和连字展开导致批注定位错误。

### 5.2 个人学习资料

- `annotations`：高亮、下划线、引用及锚点。
- `notes`：自由笔记或关联 annotation、章节、页的笔记。
- `bookmarks`、`reading_positions`：书签和阅读位置。
- `chapter_progress`：未开始/学习中/已完成/需要复习；状态与阅读位置分开。
- `study_plans`、`study_tasks`：目标日期、章节任务、完成状态。
- `knowledge_cards`：标题、正反面、来源锚点和复习状态。
- `review_items`：重点、到期日、关联对象、完成/延期状态。
- `reading_sessions`：仅记录有效活动时间；最小化、失焦或闲置时停止累计。
- `app_settings`：主题、字体、宽度、布局和阅读偏好。

学习状态由用户操作驱动；不能滚动到底就强制标为学完。仪表盘统计来自真实数据，首次运行显示空状态。

### 5.3 扩展接口

- `translation_links`：跨语言块的多对多关系，支持一段拆多段或合并；包含人工/自动、置信度、审核状态。
- 不要求中英文段落共用同一物理 ID。英文批注始终绑定英文 edition 与锚点；切换译文不覆盖原引用。
- `question_banks`、`questions`、`question_options`、`question_sources`、`practice_sessions`、`answers`：预留题库与答题记录。
- 首版题库交付 schema、格式说明、校验器和空状态；仅以明确标记的自建测试题验证数据流，不宣称官方来源。
- 尚未导入中文时显示“未导入”，不能显示虚假的翻译完成度。

## 6. 导入流水线与教材转换策略

### 6.1 导入任务状态

`待开始 → 校验 → 复制 → 提取 → 结构化 → 生成资产 → 建索引 → 校验结果 → 可用`

每个阶段可进入暂停、取消、失败；恢复时从已验证检查点继续。状态名、错误码和重试规则应在 shared 中定义。

1. 文件选择与校验：检查实际 PDF 可打开性、加密/密码状态、页数、文件大小和可用空间。扫描版与可提取文本版要区分；密码 PDF 如未支持应明确提示。
2. 受管复制：流式计算 SHA-256 并复制到 staging，避免把整本 PDF 读入内存。写入完成并校验后原子发布到书库；源文件不修改。
3. 重复检测：同一摘要提示已有教材并跳转；不同摘要即使文件名相同也不能静默覆盖旧版本。
4. 页级提取：文本、坐标、字体、字号、旋转、图像/绘制信息、书签及页标签。保留原始中间结果用于诊断，控制缓存体积。
5. 页面分区：识别正文栏、跨栏标题、页眉页脚、边注、图表区域；正文按区域组织阅读顺序。
6. 语义重建：段落合并、标题层级、列表、粗体斜体、保守去连字符。目录页、前言、参考文献和索引不能因“不属于 31 章”而被丢弃。
7. 目录提取：优先 PDF outline，结合目录页、标题和页标签校验。不把 7 Part/31 Chapter 当作可以硬编码页码的理由；Section 必须来自实际文本。
8. 图表与公式：能可靠提取的位图直接复用；简单表格转换为语义 table；复杂表格、矢量图和公式采用高分辨率区域渲染。每项绑定来源、图题和正文位置。
9. 搜索与校验：增量写 FTS5；核对覆盖页、目录边界、未归属块、空页异常和资产引用；生成转换质量报告。
10. 完成：只有必要阶段完成并提交后标为可用。有问题但可阅读的教材应显示“可用，含待校对项”，不能伪装成转换无误。

图像检测不能只枚举内嵌 raster：曲线图和表格可能完全由矢量绘制组成。区域检测与渲染要覆盖这一类，并通过真实教材抽样验证。

每页处理结果分批事务提交，任务提交具有幂等性。内存仅持有少数页和当前资产，初始并发采用保守的 1–2 页，再依据测量调整。报告阶段和真实已完成页数，不用时间估算伪造百分比。

应用重启后，运行中的任务转为“可恢复”；核验中间文件与任务记录，再继续或安全重做当前页。注入崩溃、取消、磁盘空间不足等故障验证恢复。

### 6.2 缺少教材时的边界

可先用自建 PDF 完成桌面框架、数据模型、一般导入机制和测试。取得目标教材后，才可以验证真实目录、全书正文、图表和公式质量。

不要把教材上传公开仓库、CI 或模型外部服务。自动化 CI 使用可分发的自建样例，真实教材验收在持有文件的本地环境进行。本次计划不需要用户立即上传文件；进入真实转换验证阶段前再提供。

### 6.3 转换质量的退出条件

先对包含双栏、跨页段落、不同字体、表格、曲线、公式、旋转页和图题的代表性页面做对照，形成固定评估样本。试验未通过前，不展开全部阅读器功能。

最低验收：

- 全书每页有成功提取、明确空白、仅图像或失败的状态，不能静默跳过。
- 7 Part/31 Chapter 及所有识别出的 Section 具有真实来源，31 个章首逐一核对。
- 样本中的普通正文不混栏、不把页眉夹入段落；无法修正的异常列出页码。
- 样本中的图、表、公式都能在原书模式看到；HTML 对应资产和图题经过对照，缺项登记。
- 建立自动的 Figure/Table 编号覆盖报告，同时人工核验，因为无编号资产和未识别编号无法靠该报告证明完整。
- 最终报告区分“全页处理已完成”“已人工核对的页”“发现的问题”，不得用抽样通过宣称 1,057 页均转换正确。

目标是最终完成全部首版要求。先交付最小闭环只是降低风险的阶段门，不代表删去余下功能。

## 7. 阅读、批注和搜索的关键实现约定

### 7.1 三种阅读模式

- HTML：语义节点带 block ID，支持字号、行距、宽度、主题，图表可放大并打开原书位置。
- 原书：PDF.js 按需渲染页面及文字层，限制页面缓存；不能同时把一千多页 canvas 放入 DOM。
- 对照：先实现双向页级跳转，再增加块级滚动定位。用 block_sources 映射，不按两侧滚动百分比同步；没有精确对应时提示近似页位置。

HTML 按章/Section 增量加载，保留原生文本选择与跨段批注能力。不要先引入会卸载选中文本节点的激进虚拟化；性能问题应通过测量和分块渲染解决。

三种模式都应能创建与查看笔记。PDF 原生文字选择也必须接入统一批注系统，而不是只能在 HTML 高亮。

### 7.2 锚点契约

每条批注保存：edition ID、revision ID、章节 ID、起止 block ID、起止文本偏移、exact quote、prefix/suffix、源 PDF 页索引及区域、颜色和样式。

明确偏移单位，例如显示文本的 UTF-16 code units；转换、DOM Range 和数据库采用同一约定。搜索规范化文本通过映射回到显示文本。一个批注可跨多个块。

块 ID 不使用数组下标，也不只使用正文 hash：相同正文会重复，转换器更新也会改文本。首次生成持久 ID，并保留源页、区域、文本签名等匹配依据；新修订使用匹配表迁移。

恢复定位顺序：稳定块与偏移 → 引用及上下文匹配 → 限定源页范围的候选匹配 → 标记待重新定位。多个匹配同样可信时不能静默猜测。

PDF 批注额外保存文本引用和页内规范化区域；区域适配缩放和旋转，不能只存屏幕坐标。PDF 引用与 HTML 匹配有歧义时保留源页锚点，不错误绑定段落。

需要专门覆盖：重复短句、跨段选择、去连字符、连字、特殊字符、缩放、字体变化、重启、重导入和不同转换修订。

### 7.3 搜索与备份

教材正文和个人笔记分别建 FTS 索引，支持统一搜索入口及类型过滤。结果给出真实片段、章节和页码，点击能到对应块或 PDF 页。避免在界面一次加载全书后用字符串搜索。

导出 Markdown 方便阅读；导出带 schema_version、UUID、源文件摘要和锚点的 JSON 用于恢复。需要资产时提供含 manifest、JSON 和学习资产的 ZIP；PDF 默认不包含，可单独提供明确选择。

恢复先校验 schema 和摘要，在临时区域预检再事务化导入。首版使用 UUID 与内容比较保证同一备份重复导入不重复；存在冲突时让用户选择保留当前或保留备份，避免仅凭时间戳覆盖。

缺少原书时允许恢复学习资料为“待关联教材”，保留原引用，提示导入对应 SHA-256 的 PDF。备份版本不支持时清晰报错，不部分写入。备份恢复必须验证数量、正文、锚点和来源关联，不能只检查 JSON 能解析。

## 8. 分阶段执行包与通过条件

### P0：工程约束与数据契约

工作：核对仓库和工具；创建项目骨架；确定命令；写 architecture、data-model、ipc-contracts、acceptance-matrix；建立自建 PDF 样例；锁定初步依赖。

交付：可启动的最小桌面窗口、数据库初始化、版本决策记录、数据与 IPC 契约。

通过：开发启动、生产构建、类型检查成功；本地 SQLite 写入后重启能读回。未拿到原书可进行，但文档标记原书验证待办。

### P1：Windows 与解析可行性验证（两个必须早过的门）

Windows 工作：用最小应用打包 NSIS/便携目录，验证 SQLite 原生模块、PDF worker、字体/CMaps 和区域渲染库都被正确带入。核对 Windows 10/11 支持范围。

解析工作：真实教材一旦可用，先做代表页转换和章首/目录识别；建立图文对照与问题清单。没有原书时只能报告通用解析能力通过。

交付：Windows 冒烟包与报告、转换样本报告、最终首版解析技术决策。

## 10. Windows 构建与离线交付细节

开发环境可在 Linux 完成大部分逻辑与自动化验证，但 Windows 原生依赖和安装行为须在 Windows 验证。没有 Wine 不妨碍规划或通用代码开发；不能因此声称 EXE 已运行。

优先使用用户可控的 Windows 构建机。也可准备 GitHub Actions Windows workflow；在未获得授权前不推送、不触发涉及外部上传的流程。公开仓库尤其不能包含教材、笔记或源 PDF 派生内容。

Windows 构建脚本负责锁文件安装、Electron native rebuild、typecheck、测试、生产构建、electron-builder、产物校验。开发完成后固定并记录这些命令的真实名称，避免文档与 package.json 不一致。

安装包必须验证 asar/unpack 中的 native module、worker 路径、字体、CMaps 和资产协议。清洁 Windows 上不能要求用户预装 Node、Python 或执行开发命令。

打包前清查：教材/截图/用户 SQLite/缓存/密钥不得误入源码 ZIP 或安装包。安装包中的依赖许可证说明按实际使用版本生成。若安装包未签名，交付说明写明实际签名状态和系统可能显示的提示，不能声称已签名。

源码 ZIP 含完整源码、锁文件、README、构建脚本、迁移、可分发样例、数据说明和测试报告，不包含 node_modules 或真实教材。ZIP 的展开验证与 EXE 的可运行验证分开记录。

## 11. 模型交接与任务拆分方式

建议顺序调用模型完成各阶段；每次只给一个阶段，保持同一套仓库和已接受的数据契约。不要一次让模型“完成所有功能”后只交付截图。

所有实施模型先读：本方案、项目 README、适用 AGENTS.md、docs/architecture.md、data-model.md、ipc-contracts.md 和 handoff.md。不存在的文档由 P0 创建，后续按事实维护。

每阶段交接记录必须包含：

1. 当前提交/分支、工作区状态、修改文件与实现范围。
2. 已完成需求、未完成需求、已知缺陷，不能把计划当成果。

4. 数据库/IPC 变更、迁移方式及对已有数据的影响。
5. 下一阶段最小必要任务和阻塞，不重复已通过的无关检查。

阶段间不随意重建项目、不替换技术栈、不清空学习数据。需要修改公共契约时先写决策和迁移，再改实现。
