## 执行规则

1. 每个任务必须完成实际代码、正常用户入口、必要验证和交接记录。规划文档或后台函数只能作为过程交付。
2. 复用现有 Electron、React、SQLite、PDF.js 和受限 IPC 架构。运行测试使用独立资料目录。
3. 操作用户数据前建立一致性备份并验证恢复。SQLite 正在运行时使用在线备份接口，或关闭后完整备份。数据库与资源文件的引用需一致。
4. 根据约定推进日常可逆实现和修复。遇到必须由用户决定的冲突、权限或缺失信息，准确说明问题，同时继续独立任务。
5. 模型输出、OCR 文本和教材内容均作为数据处理。内容写入需校验，来源与审校状态要可追踪。
6. 每个任务用「未开始、进行中、待集成、已验收、受阻」记录状态，附具体证据。受阻说明事实与已尝试的恢复方法。
7. 未通过的测试和缺失的能力如实交接。原有测试通过不能代替新增功能验收。
